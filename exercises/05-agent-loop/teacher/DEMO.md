# دموی مدرس — تمرین ۵: Agent و حلقه

زمان پیشنهادی: ۵۰ تا ۶۰ دقیقه. سؤال محوری این است: چه زمانی یک LLM با tool calling ساده داریم، و چه زمانی مدل در حلقه با دیدن نتیجه، گام بعد را انتخاب می‌کند؟

## اجرا

```bash
# ترمینال اول
python3 exercises/05-agent-loop/student/app.py

# ترمینال دوم
python3 exercises/05-agent-loop/teacher/app.py
```

نسخهٔ دانشجو در `http://127.0.0.1:8781` و دموی مدرس در `http://127.0.0.1:8782` است. هر نسخه دادهٔ JSON جداگانه دارد و تنظیمات `.env` ریشه را می‌خواند.

## جریان کلاس

| زمان | اجرا | نکته |
|---|---|---|
| ۰–۱۰ | تمرین ۳ را به یاد بیاورید | یک tool call: مدل درخواست می‌دهد، Python اجرا می‌کند و مدل جواب می‌دهد |
| ۱۰–۲۰ | سناریوی «پول کم شده، دسترسی ندارم» را اجرا کنید | صفحه و ترمینال تصمیم‌های مدل و مشاهده‌های Python را نشان می‌دهند |
| ۲۰–۳۵ | `answer()` را خط‌به‌خط بخوانید | هر نتیجه به history پیام‌های مدل اضافه می‌شود و مدل دوباره تصمیم می‌گیرد |
| ۳۵–۴۵ | دسترسی فعال و پرداخت ناموفق را امتحان کنید | Agent باید قبل از ساخت تیکت متوقف شود یا علت را توضیح دهد |
| ۴۵–۵۵ | سقف ۵ ابزار و تیکت تکراری را بحث کنید | شرط توقف، هزینه، حلقهٔ بی‌پایان و idempotency |

## رفتار مورد انتظار

- `en-1043` (مبانی یادگیری ماشین): پرداخت `paid` و دسترسی `inactive` است؛ یک تیکت `ticket-5001` ساخته می‌شود.
- `en-1042` (Python برای تحلیل داده): دسترسی `active` است؛ تیکت لازم نیست.
- `en-1044` (مبانی هوش مصنوعی): پرداخت `failed` است؛ ابزار Python ساخت تیکت را رد می‌کند.
- اجرای دوبارهٔ تیکت برای ثبت‌نامی که تیکت باز دارد، شناسهٔ همان تیکت را برمی‌گرداند.
- پس از ۵ اجرای ابزار، اجرای ابزار ششم ممنوع است؛ مدل فقط جمع‌بندی می‌کند.
- برای «سلام»، پاسخ کوتاه بدون فراخوانی ابزار داده می‌شود. اگر مدل در یک گام چند ابزار پیشنهاد کند، برنامه فقط اولی را اجرا می‌کند و سپس با نتیجهٔ آن از مدل تصمیم بعدی را می‌خواهد.

## آنچه در کد نشان دهید

- `while tool_steps < MAX_TOOL_STEPS` هستهٔ loop است.
- `messages` هم پیام‌های کاربر/مدل و هم نتیجه‌های ابزار با `tool_call_id` را نگه می‌دارد.
- Python دادهٔ واقعی بیرونی ندارد؛ همه‌چیز JSON محلی است.
- خود مدل تصمیم می‌گیرد شواهد کافی است یا ابزار دیگری لازم دارد؛ Python مالکیت و شروط تیکت را کنترل می‌کند.
- سقف گام‌ها از ادامهٔ بی‌پایان جلوگیری می‌کند. شرط توقف عادی، پاسخ متنی مدل بدون tool call است.

## جمع‌بندی

در Tool Calling تک‌مرحله‌ای، مسیر از قبل یک رفت‌وبرگشت دارد. در Agent loop، برنامه نتیجه را به مدل برمی‌گرداند و مدل مسیر را ادامه می‌دهد تا پاسخ بدهد یا سقف اجرا برسد. چارچوب خاصی لازم نیست؛ حلقه در Python دیده می‌شود.
