# تمرین ۵ — Agent و حلقهٔ ابزار

## مسئله

کاربر می‌گوید پول دوره از حسابش کم شده اما دسترسی ندارد. دستیار باید دوره را پیدا کند، پرداخت را بخواند، دسترسی را بررسی کند و فقط وقتی هر دو شاهد با هم مغایرت دارند تیکت بسازد.

در تمرین ۴ یک درخواست مدل و حداکثر یک اجرای ابزار داشتیم. این‌بار مدل بعد از دیدن هر نتیجه دوباره تصمیم می‌گیرد:

```text
درخواست کاربر
  → مدل ابزار مناسب را انتخاب می‌کند
  → Python ابزار را اجرا می‌کند
  → نتیجه به مدل برمی‌گردد
  → مدل تصمیم می‌گیرد: ابزار بعدی یا پاسخ نهایی؟
```

## اجرا

از ریشهٔ repo:

```bash
python3 exercises/05-agent-loop/student/app.py
```

صفحه در http://127.0.0.1:8781 باز می‌شود. تنظیمات مدل از `.env` ریشه خوانده می‌شوند. حلقه را در `student/agent.py` کامل کنید.

## مأموریت کدنویسی

فقط تابع `answer(question, history)` نیاز به تکمیل دارد. ابزارها و دادهٔ ساختگی آماده‌اند. در این تابع:

1. تا وقتی کمتر از `MAX_TOOL_STEPS` ابزار اجرا شده، پیام‌ها را همراه schema ابزارها به مدل بفرستید.
2. اگر مدل `tool_calls` نداد، متن پاسخ را برگردانید و حلقه را تمام کنید.
3. در هر گام فقط یک ابزار را dispatch کنید.
4. درخواست ابزار مدل و نتیجهٔ Python را با `tool_call_id` درست به `messages` اضافه کنید تا مدل آن نتیجه را مشاهده کند.
5. شمارنده را زیاد کنید؛ بعد از رسیدن به سقف ۵ اجرا، ابزار دیگری اجرا نکنید و از مدل بخواهید بدون ابزار جمع‌بندی کند.

از Coding Agent بخواهید اول همین مسیر را در کد نشان دهد، بعد TODOها را یکی‌یکی پیاده کند. در کلاس باید بتوانید توضیح دهید هر دور حلقه چه چیزی به مدل می‌دهد و چه چیزی از Python پس می‌گیرد.

## سناریوهای آزمایش

- `پول دوره مبانی یادگیری ماشین از حسابم کم شده ولی هنوز دسترسی ندارم؛ بررسی کن و اگر مغایرت تأیید شد تیکت بساز.` انتظار: پیدا کردن `en-1043`، پرداخت موفق، دسترسی غیرفعال و ساخت یک تیکت.
- `دسترسی من به دوره پایتون فعاله؟` انتظار: خواندن وضعیت و پایان بدون ساخت تیکت.
- `برای دوره مبانی هوش مصنوعی پول پرداخت کردم؟` انتظار: پرداخت ناموفق؛ تیکت دسترسی ساخته نشود.
- همان درخواست تیکت را دوباره بفرستید. انتظار: تیکت باز تکراری ساخته نشود.

## داده و محدودیت‌ها

تمام داده‌ها فایل JSON محلی‌اند و هیچ سرویس واقعی صدا زده نمی‌شود. ابزار تیکت، مالکیت، پرداخت موفق، غیرفعال‌بودن دسترسی و تکراری‌نبودن تیکت را در Python بررسی می‌کند. بعد از حداکثر ۵ اجرای ابزار حلقه متوقف می‌شود. دکمهٔ «بازنشانی داده» تیکت‌ها را از فایل seed برمی‌گرداند.
