# دموی مدرس — تمرین ۶: Planning در حلقهٔ Agent

زمان پیشنهادی: ۵۰ تا ۶۰ دقیقه. هدف این است که شرکت‌کننده تفاوت برنامهٔ قابل‌مشاهده و اجرای واقعی ابزار را ببیند و اثر مشاهده‌های تازه بر برنامه را توضیح دهد.

## اجرا

```bash
# ترمینال اول
python3 exercises/06-planning/student/app.py

# ترمینال دوم
python3 exercises/06-planning/teacher/app.py
```

نسخهٔ دانشجو در `http://127.0.0.1:8783` و دموی مدرس در `http://127.0.0.1:8784` است. هر دو نسخه از دادهٔ JSON مستقل و `.env` ریشه استفاده می‌کنند.

## اجرای سناریو

از نمونهٔ چندبخشی UI استفاده کنید. برنامهٔ آغازین باید ابتدا دوره‌ها و شناسه‌ها را پیدا کند، بعد پرداخت و دسترسی مبانی یادگیری ماشین را بررسی کند، در صورت مغایرت تیکت بسازد و سپس پرداخت و دسترسی مبانی هوش مصنوعی را بررسی کند.

در UI و ترمینال، در هر دور این سه بخش را دنبال کنید:

1. plan تازه با شمارهٔ نسخه و شواهد
2. ابزار عملیاتی که مدل انتخاب کرد یا پاسخ نهایی
3. نتیجهٔ Python که به مدل برمی‌گردد

به برنامهٔ بعد از مشاهدهٔ پرداخت ناموفق برای مبانی هوش مصنوعی توجه کنید؛ مدل باید ساخت تیکت را از برنامه حذف کند.

## سناریوهای دیگر

- دسترسی فعال دورهٔ Python: وضعیت را بگوید و تیکت نسازد.
- درخواست ساخت تیکت برای مبانی هوش مصنوعی با پرداخت ناموفق: Python با دلیل رد کند.
- اجرای دوبارهٔ سناریوی مبانی یادگیری ماشین: تیکت باز تکراری ساخته نشود.
- پس از رسیدن به ۷ اجرای ابزار: اجرای ابزار متوقف و مدل بدون ابزار جمع‌بندی کند.
- تغییر `steps` به مقدار نامعتبر یا بازگرداندن ابزار اشتباه در دور Planning: ابزار عملیاتی اجرا نشود.

## نکته‌های بحث

- Planning یک متن کوتاه و قابل‌مشاهده است؛ برنامه به‌تنهایی صحت اجرا را تضمین نمی‌کند.
- مدل در هر دور یک بار Planning اجباری و سپس یک بار انتخاب ابزار/پاسخ دارد؛ این کار هزینهٔ مدل را بیشتر می‌کند.
- نتیجهٔ ابزار در پیام‌های مدل قرار می‌گیرد؛ plan نسخهٔ بعد باید از شواهد تازه استفاده کند.
- اگر مدل پیش از خواندن دادهٔ لازم پاسخ بدهد، حلقه ابزارهای جاافتاده را از او می‌خواهد؛ اگر پاسخ صریح با دادهٔ خوانده‌شده تناقض داشته باشد، جمع‌بندی تأییدشدهٔ Python جای آن را می‌گیرد.
- Python شروط تیکت را مستقل کنترل می‌کند. مدل نمی‌تواند با نوشتن plan شرط پرداخت یا دسترسی را دور بزند.
- سقف هفت ابزار عملیاتی، حلقهٔ بی‌پایان را محدود می‌کند؛ درخواست‌های Planning در این سقف شمرده نمی‌شوند.

پس از اجرا، دکمهٔ «بازنشانی داده» تیکت‌های مدرس را به حالت seed برمی‌گرداند.
