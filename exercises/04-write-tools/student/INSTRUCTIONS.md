# تمرین ۴ — مکالمهٔ چندنوبته و اکشن نوشتنی

## مسئله

در تمرین قبل وضعیت را می‌خواندیم، اما داده را تغییر نمی‌دادیم. این بار گفت‌وگو را ادامه می‌دهیم: اول کاربر فهرست سفارش‌هایش را می‌خواهد؛ سپس می‌گوید «دومی را لغو کن». دستیار باید از پیام قبلی بفهمد منظور کدام ثبت‌نام است و ابزار لغو را فقط برای پیام روشنِ لغو در دسترس بگذارد.

```text
نوبت ۱: فهرست سفارش‌ها → پاسخ با شناسه‌ها
نوبت ۲: پیام تازه + تاریخچه → ابزار لغو → بررسی Python → تغییر JSON → پاسخ نهایی
```

## اجرا

از ریشهٔ پروژه اجرا کنید:

```bash
python3 exercises/04-write-tools/student/app.py
```

صفحهٔ http://127.0.0.1:8779 را باز کنید. تنظیمات LLM از `.env` ریشه خوانده می‌شوند. تاریخچهٔ مکالمه در همان تب مرورگر می‌ماند و تغییر ثبت‌نام در فایل محلی JSON حفظ می‌شود. برای شروع دوباره، «گفت‌وگوی تازه» تاریخچه را پاک می‌کند و «بازنشانی داده» فایل را به حالت اولیه برمی‌گرداند.

## TODOها را به ترتیب کامل کنید

1. تعریف ابزار `cancel_enrollment(enrollment_id)` را به schemaها اضافه کنید.
2. `list_my_orders()` را کامل کنید تا سفارش‌های کاربر آزمایشی `u-104` را همراه شناسهٔ سفارش، شناسهٔ ثبت‌نام و وضعیت‌ها برگرداند.
3. `cancel_enrollment()` را پیاده کنید: رکورد را پیدا کنید؛ مالکیت، وضعیت `pending` و شروع‌نشدن جلسه را در Python بررسی کنید؛ فقط در صورت مجازبودن، فایل `enrollments.json` را با وضعیت `cancelled` بنویسید.
4. dispatch را کامل کنید تا ابزار لغو فقط وقتی پیام فعلی صریحاً لغو/حذف می‌خواهد قابل اجرا باشد. در این سناریو «حذف سفارش» یعنی لغو ثبت‌نام آزمایشی، نه پاک‌کردن دائمی رکورد. پیام قبلی به مدل کمک می‌کند «دومی» را به شناسهٔ درست وصل کند؛ خود Python همچنان بررسی‌های مالکیت و شرایط را انجام می‌دهد.

تابع `answer(question, history)` و رابط چت مسیر تاریخچه و رفت‌وبرگشت مدل را نشان می‌دهند. از Coding Agent بخواهید ابتدا این مسیر را توضیح دهد، سپس هر TODO را جداگانه کامل کند.

## سناریوها

- پیام اول: `وضعیت سفارش‌های من چطوره؟` باید دو سفارش کاربر آزمایشی را با شناسه‌ها فهرست کند.
- پیام دوم در همان گفت‌وگو: `دومی رو لغو کن` باید `en-1043` را هدف بگیرد و وضعیتش را به `cancelled` تغییر دهد.
- عبارت `سفارش مبانی یادگیری ماشین رو حذف کن` هم باید به‌عنوان درخواست لغو روشن شناخته شود.
- تلاش برای لغو ثبت‌نام active مانند `en-1042` باید رد شود و فایل را تغییر ندهد.
- شناسهٔ ناموجود یا متعلق به کاربر دیگر نباید تغییر کند.
- اگر کاربر فقط وضعیت بپرسد، ابزار لغو اصلاً در اختیار مدل نیست.
- بعد از لغو، همان ثبت‌نام را بخوانید؛ پس از بازنشانی داده، وضعیت اولیه برمی‌گردد.

## محدودیت و تحویل

- داده‌ها ساختگی‌اند. ابزار فقط ثبت‌نام را لغو می‌کند؛ بازپرداخت پول انجام نمی‌شود.
- ارسال «لغو کن» در نوبت دوم مجوز اقدام است؛ دکمهٔ تأیید جداگانه نداریم. بررسی مالکیت و شرایط و نوشتن فایل در Python است.
- تحویل: TODOهای کامل‌شده و شرح کوتاهی از این‌که تاریخچه چطور «دومی» را به `en-1043` وصل کرد و کدام شرط Python جلوی لغو ثبت‌نام active را گرفت.
